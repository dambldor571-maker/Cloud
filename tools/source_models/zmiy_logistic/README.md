# НРК «Змій Логістичний» (Rovertech, 2026) — 3D-модель

Hero-asset без LOD, зібраний процедурно скриптами Blender з нуля за ТЗ (`HANDOFF.md`) і фото.
Перевірено на **Blender 4.5.14 LTS** (API 4.2+).

![3/4 спереду](renders/zmiy_front34.jpg)

| Файл | Що це |
|---|---|
| `zmiy_logistic.blend` | сцена: модель, модулі (сховані), колізії; текстури — відносні шляхи `textures/` |
| `zmiy_logistic.fbx` | модель + колізії `UCX_*` (Unreal); текстури лежать поряд у `textures/` |
| `zmiy_logistic.glb` | модель для Godot / веб, текстури вбудовані (2048 px) |
| `zmiy_logistic_modules.glb` | опційні модулі в тих самих координатах: Starlink, вантаж, вила-концепт |
| `textures/` | PBR-карти (див. нижче) і наліпки логотипу |
| `renders/` | рендери: 3/4 спереду, збоку, спереду, згори, ззаду, знизу, з модулями |
| `zmiy_build.py` | геометрія й ієрархія (параметри — словник `P` на початку) |
| `zmiy_texture.py` | UV, запікання масок у Cycles, складання текстур зі зносом |
| `zmiy_export.py` | експорт `.blend/.fbx/.glb` і рендери |
| `make_decals.py` | генерує текстури наліпок (Pillow) |

## Як перезібрати

```
blender -b --factory-startup --python zmiy_build.py --python zmiy_texture.py --python zmiy_export.py
```

- Тільки геометрія з простими матеріалами: відкрити `zmiy_build.py` у Blender → Scripting → Run Script.
- Роздільність текстур — `TEX_RES` у `zmiy_texture.py` (або `ZMIY_TEX_SCALE=0.5` для швидкої перевірки).
- `ZMIY_MASK_CACHE=_cache` зберігає запечені маски: повторне складання текстур без перезапікання.
- `ZMIY_SAMPLES`, `ZMIY_RES_PCT` — якість/розмір рендерів, `ZMIY_NO_RENDER=1` — без рендерів.
- Повний прогін на 4 ядрах CPU без GPU: ~45 хв текстури (Body 4K — ~30 хв) + ~20 хв рендери (Cycles, 160 семплів).
- Лише рендери з готового файлу: `ZMIY_NO_EXPORT=1 ZMIY_VIEWS=front34,side blender -b zmiy_logistic.blend --python zmiy_export.py`.
- Скрипти перевірено також у Blender 5.2 (модуль `bpy` 5.2.2): збірка, текстури й експорт проходять.

## Ієрархія, осі, масштаб

```
Zmiy_Logistic            empty на землі під центром, (0, 0, 0)
├─ Body                  корпус, кузов, ніс, корма, фаркоп, кріплення          (матеріал Zmiy_Body)
│  ├─ Decal_Logo_Nose    наліпки — окремі площини (товарний знак Rovertech,
│  ├─ Decal_Logo_Rear     можна сховати або замінити, матеріали Zmiy_Decal_*)
│  └─ Decal_Text_Rear
├─ Cage                  дуга каркаса, діагоналі, поручні, кронштейни          (Zmiy_Frame)
├─ Camera                блок камери; півот у точці кріплення під дугою        (Zmiy_Frame)
├─ Wheel_FL / FR / RL / RR   півот у центрі колеса, обертання навколо локальної X  (Zmiy_Wheel)
├─ Module_Starlink / Module_Cargo / Module_Forks   сховані опційні модулі
└─ UCX_Zmiy_Logistic_00…06   прості опуклі колізії (колекція Zmiy_Collision)
```

- Blender: **X праворуч, Y вперед (ніс), Z вгору**, 1 юніт = 1 м, земля на Z = 0.
- glTF: ніс дивиться в −Z (це «вперед» у Godot). FBX: експорт з `-Z forward, Y up`.
- Ліві колеса — дзеркальний меш правих (той самий UV), тож «ялинка» протектора однаково спрямована
  на обох бортах (вершина шеврона вгорі колеса дивиться вперед, як на тракторних шинах).
- Колеса інстансні: 2 меші (`Zmiy_Wheel_R`, `Zmiy_Wheel_L`) на 4 об'єкти.

## Конструкція — що уточнено по фото

- **Каркас.** На фото 03/04 і на фото ззаду (`IMG_2920-2-2.jpg`) видно, що це одна поперечна
  П-подібна дуга (Ø45, радіус загинів 0,16) на передньому краї вантажного кузова. Під верхньою
  трубою по центру — блок камери на хомутах, від верхньої труби до стійок — дві діагональні тяги Ø22.
  Ноги дуги стоять на пластинах 104×132×8 з косинками й 4 болтами.
- **Поручні** з обох боків: задня нога → горизонталь на 0,945 → сходинка вгору → приварено до стійки
  дуги на 1,07. Дві проміжні стійки. Ноги поручнів заходять усередину борту і кріпляться парами болтів.
- **Кузов-«ванна»**: палуба 4 мм + борти 5 мм з рядом прорізів (рядки 62×24, 40×15 і Ø11 — справжні
  отвори) і парами болтів, фаски на кінцях бортів як на фото.
- **Ніс**: трапецієподібний лобовий лист із зрізаними нижніми кутами (як на CAD-рендерах), губа по
  периметру переду палуби, вушка для підйому на кутах, П-ручка, буксирувальні отвори в нижніх кутах,
  стрижень праворуч, гак ліворуч, кронштейни з гаками на бортах носа.

## Текстури і матеріали (PBR metal/rough)

Три набори, один матеріал на набір: `Zmiy_Body` (4096, ~800 px/м), `Zmiy_Frame` (каркас + камера, 2048),
`Zmiy_Wheel` (2048; один атлас на 4 колеса). Меші тріангульовані до запікання, тож дотичний простір
у рушії збігається із запеченими нормалями. У GLB текстури вбудовані зменшеними до 2048. Для кожного набору:

| Карта | Формат |
|---|---|
| `Zmiy_<Set>_BaseColor.png` | sRGB |
| `Zmiy_<Set>_Normal.png` | дотичний простір, **OpenGL (+Y)** — Godot/Blender; для Unreal/DirectX інвертувати G |
| `Zmiy_<Set>_ORM.png` | R = AO, G = Roughness, B = Metallic (glTF/Unreal) |
| `Zmiy_<Set>_AO.png`, `_Roughness.png`, `_Metallic.png` | ті самі канали окремими сірими файлами — Unit Workshop читає їх з каналу R |

FBX несе лише BaseColor і Normal (ORM через вузол Separate Color у FBX не записується) — у рушії
підключити `Zmiy_<Set>_ORM.png` вручну. GLB має повний матеріал (metallicRoughness + occlusion).

Кольори — за таблицею ТЗ: олива #434A37 (rough 0,7–0,8), труби #1A1A1A (0,45), шини #1C1C1C (0,9),
диски #151515 (0,5), цинк #8A8A85 (metal 1), скло, корпус камери #2A2A2A, помаранчева ручка.
Знос складено процедурно в `zmiy_texture.py` із запечених масок (AO великий/малий, позиція, нормаль,
ребра, ID матеріалу) і 3D-шуму у світових координатах (без швів між острівцями):

- сколи фарби на опуклих ребрах — спершу ґрунт, у центрі сколу голий метал; затерті верхи поручнів;
- подряпини на палубі, потьоки на вертикальних поверхнях, вигорання фарби згори;
- пил на горизонталях і в щілинах; бруд знизу корпусу, бризки біля коліс, бруд на днищі;
- шини: глина між ґрунтозачепами, обтерті кромки зачепів; диски: сколи на закраїнах;
- карта нормалей: запечені фаски (Bevel, 3,5 мм) + рельєф сколів і бруду.

## Оригінальний `zmiy_blockout.py` з пакета

Запускається в Blender 4.5 без помилок, але має вади, через які його замінено на `zmiy_build.py`:

- порожній об'єкт `Camera` конфліктує зі стандартною камерою сцени → стає `Camera.001`
  (у новому скрипті чужий об'єкт перейменовується на `Camera.scene`);
- колекція різців для прорізів вкладена в колекцію моделі → потрапила б в експорт; булеві операції
  лишалися живими модифікаторами;
- розміри носа й каркаса з ТЗ не збігаються з фото (див. таблицю вище).

## Unit Workshop (рендер спрайтів для гри)

- Відкрити `zmiy_logistic.glb`; частини згрупуються як `Body`, `Cage`, `Camera`, `Wheel`
  (роль `wheel` вгадується за назвою, `Body` → корпус).
- Фарба: «з файлу» (`paint_source: file`) — береться BaseColor і нормалі з GLB; зношення шейдера
  гри тоді краще тримати низьким (0–0,3), бо бруд і сколи вже є в текстурі.
- Для точнішого світла додати набір текстур «вся модель» або для частин: `ao`, `roughness`,
  `metallic_map` — файли `textures/Zmiy_<Set>_AO/Roughness/Metallic.png` (Body → `Zmiy_Body_*`,
  Cage і Camera → `Zmiy_Frame_*`, Wheel → `Zmiy_Wheel_*`).
- Ніс у GLB дивиться в −Z; у Unit Workshop «вперед» — +X, тож потрібен поворот `yaw` на 90°.
- Довжина для масштабу (`length_m`): 1,76 м з кулею фаркопа (найдовша горизонтальна сторона).

## Відомі обмеження

- Фото днища, вил і точних креслень немає — ці частини реконструйовані (див. таблицю рішень).
- Розміри — з фото (похибка ~5–10 %). Найменш певне — висота лобового листа: на фото 04 він
  відносно колеса трохи вищий (≈10 %), ніж у моделі; змінюється параметрами `chin_z`, `nose_lip_z0`.
- Логотип — стилізоване наближення трафарету, не оригінальний файл виробника.
- Шви зварювання не моделювались окремо (лише зварні валики біля ніг дуги й поручнів).
