# Збирання та налаштування на Raspberry Pi 4

> Статус: інструкцію складено за документацією, **на реальному залізі ще не перевірено**.
> Пункти, які треба підтвердити при першому запуску, позначено ⚠.

## Компоненти

| Компонент | Призначення | Примітка |
|---|---|---|
| Raspberry Pi 4 (2 ГБ достатньо) | обробка | Raspberry Pi OS Lite (Bookworm, 64-bit) |
| Декодер CVBS→CSI на **ADV7280-M** | аналогове відео в Pi | альтернатива — USB-грабер (UVC), див. нижче |
| Кабель TRRS 3.5 мм → RCA | композитний вихід Pi 4 на монітор | розпіновка TRRS у різних кабелів різна ⚠ |
| Реле **DPDT** (дві групи контактів), 5 В, з транзисторним/оптронним входом | обхід при збої | див. схему |
| Активний зумер 5 В + NPN-транзистор (BC547/2N2222) + резистор 1 кОм | звук | |
| (бажано) модуль RTC **DS3231** | правильний час без інтернету | Pi 4 не має годинника реального часу |
| Блок живлення 5 В / 3 А | | монітор і камера — від свого живлення 12 В |

## Схема підключення

### Відео і реле обходу

Реле має **дві** групи контактів, щоб камера ніколи не була підключена
одночасно до двох входів (інакше подвійне навантаження 75 Ом — картинка вдвічі темніша).

```
                  група 1                                група 2
Камера ── COM1 ─┬─ NO1 ──► вхід декодера ADV7280-M    Pi CVBS вихід ──► NO2 ─┐
                └─ NC1 ───────────────────────────────────────────────► NC2 ─┴─ COM2 ──► Монітор
```

- **Реле знеструмлене** (Pi вимкнена, завантажується, програма впала або зависла):
  камера → монітор напряму.
- **Реле ввімкнене** (програма працює і показує кадри): камера → Pi → монітор з рамками.

Програма вмикає реле, лише поки цикл виведення справді оновлює кадри,
і відпускає його, якщо кадрів немає довше за `relay.stall_timeout` (1 с).
Нюанс: поки реле відпущене, декодер не отримує сигналу. ADV7280-M у цьому стані
продовжує видавати порожні кадри ⚠, тож програма бачить, що живе, і вмикає реле.

**Зависання всієї ОС.** Якщо зависне ядро, GPIO може залишитись у «1» і реле не відпуститься.
Захист — два рівні:

1. Апаратний сторож Pi (обов'язково): ОС перезавантажиться за ~15 с, а під час
   перезавантаження GPIO стає входом → реле відпускається. На вході модуля реле
   з активним високим рівнем поставте резистор 10 кОм на GND, щоб вхід, що «висить у повітрі»,
   не вмикав реле.
2. (опційно, миттєвий) `relay.mode: pulse` — програма подає меандр 10 Гц, а реле вмикає
   простий накачувальний ланцюжок (конденсатор + діоди + транзистор) або
   модуль апаратного сторожа: зникли імпульси → реле відпущене.

### Зумер

```
GPIO17 ──[1 кОм]──► база NPN
                    емітер ──► GND
5V ──► (+) зумер (−) ──► колектор NPN
```

### Використані виводи (нумерація BCM)

| GPIO | Пін | Призначення |
|---|---|---|
| 17 | 11 | зумер |
| 27 | 13 | реле обходу |
| 2, 3 | 3, 5 | I²C — модуль RTC DS3231 (якщо є) |

## Налаштування ОС

1. Запишіть Raspberry Pi OS Lite (64-bit) через Raspberry Pi Imager, увімкніть SSH.

2. `/boot/firmware/config.txt`:

   ```ini
   # Композитний вихід на Pi 4 (за замовчуванням вимкнений)
   enable_tvout=1
   dtoverlay=vc4-kms-v3d,composite

   # Аналоговий декодер на порту камери ⚠ перевірити назву/параметри оверлею
   dtoverlay=adv728x-m,adv7280m=1

   # Апаратний сторож
   dtparam=watchdog=on

   # RTC (якщо є модуль DS3231)
   dtoverlay=i2c-rtc,ds3231
   ```

3. `/boot/firmware/cmdline.txt` — дописати в **той самий рядок**:

   - PAL: `video=Composite-1:720x576@50ie vc4.tv_norm=PAL consoleblank=0 vt.global_cursor_default=0`
   - NTSC: `video=Composite-1:720x480@60ie vc4.tv_norm=NTSC consoleblank=0 vt.global_cursor_default=0`

   Стандарт тут, у `config.yaml` (`source.standard`) і на камері має збігатися.

4. Сторож systemd — у `/etc/systemd/system.conf`:

   ```ini
   RuntimeWatchdogSec=15
   ```

5. Щоб текстова консоль не малювала поверх відео:

   ```bash
   sudo systemctl disable getty@tty1
   ```

6. Перезавантажте й перевірте:

   ```bash
   cat /sys/class/graphics/fb0/virtual_size   # 720,576 (PAL) або 720,480 (NTSC)
   v4l2-ctl --list-devices                     # має бути пристрій декодера
   v4l2-ctl -d /dev/video0 --get-standard      # ⚠ може знадобитися --set-standard=pal
   ```

## Встановлення програми

```bash
sudo apt install -y git python3-venv python3-opencv python3-numpy python3-yaml python3-gpiozero
git clone <адреса репозиторію> ~/vigil && cd ~/vigil
# Беремо OpenCV/NumPy з системи (зібрані під Pi), тому --system-site-packages і --no-deps
python3 -m venv --system-site-packages .venv
.venv/bin/pip install --no-deps -e .
cp config.example.yaml config.yaml

# Пробний запуск (Ctrl+C — вихід)
.venv/bin/python -m vigil -c config.yaml

# Автозапуск
sudo cp deploy/vigil.service /etc/systemd/system/
sudo systemctl enable --now vigil
journalctl -u vigil -f
```

## Альтернатива: USB-грабер

Якщо з ADV7280-M виникнуть проблеми — USB-грабер (UVC, напр. на MS2109 чи UTV007) працює
без драйверів: підключити в USB, у `config.yaml` залишити `uri: "0"`. Затримка трохи
більша (+1–2 кадри), а частина дешевих граберів стискає відео в MJPEG.

## Налаштування чутливості на місці

1. Запишіть кілька хвилин відео з камери на місці встановлення:
   `.venv/bin/python -m vigil -c config.yaml --display file --out test.avi --max-frames 3000`
2. Подивіться, де виникають хибні рамки (гілки, трава, тіні) — додайте `motion.ignore_zones`.
3. Хибні спрацьовування на шум — збільшіть `motion.var_threshold` або `motion.min_area_pct`.
4. Рамка з'являється надто пізно — зменшіть `tracker.min_hits`.
