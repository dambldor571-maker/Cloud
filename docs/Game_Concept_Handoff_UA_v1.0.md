# 1. Загальна концепція

Гра — покрокова військова стратегія для Android із можливістю в майбутньому без переписування ядра перенести проєкт на Windows.

Основні референси:

- **Panzer Tactics** — структура покрокової тактики, гексова карта, юніти, дальності, захоплення об'єктів.
- **Civilization V** — читабельність великої гексової карти, псевдо-3D подача, камера, масштабування.
- **Dorfromantik** — ідеї для процедурного формування природних кластерів, сумісності країв гексів, шаблонів місцевості, мереж доріг/річок і seed-генерації.

## 1.1. Сетинг

- Сучасна війна.
- Сторони поки мають нейтральні назви: **Сторона A, Сторона B, Сторона C...**
- Використовується **реальна сучасна бойова техніка**.
- Кожна сторона має **свій унікальний набір реальної техніки**.
- Політичну/державну прив'язку сторін поки не фіксуємо.

## 1.2. Формат гри

- Одна довга кампанія на **одній безперервній гексовій карті**.
- Окремих бойових арен/переходів у тактичний режим немає.
- Немає обмеження за кількістю ходів.
- Поточна базова умова перемоги: **захопити всі ключові точки противника**.
- Дипломатії, союзів, нейтралітету та перемир'я поки немає.
- Погоди та циклу день/ніч поки немає.
- Повноцінний флот відкладено.
- БПЛА відкладено.
- РЕБ відкладено.

# 2. Візуальна модель і камера

- Псевдо-3D.
- Юніти та більшість об'єктів — 2D-спрайти.
- Орієнтовний кут камери — **65°**.
- Вільний zoom із обмеженим мінімумом/максимумом.
- Близький zoom: повні спрайти й деталі.
- Середній zoom: спрощена деталізація.
- Далекий zoom: юніти переходять у іконки/маркери, дрібний декор не відмальовується.
- Візуальні пагорби, схили та нерівності дозволені, але **ігрової системи висоти поки немає**.
- Межі лісу та забудови можуть візуально заходити на сусідні гекси, але кожен гекс має один основний ігровий тип.

# 3. Платформи та технічний принцип

## 3.1. Цільові платформи

- Перша ціль — **Android**.
- Архітектуру одразу робити так, щоб проєкт можна було перенести на **Windows** без переписування ігрового ядра.

## 3.2. Платформонезалежне ядро

Спільними мають бути:

- карта та генератор;
- гексова логіка;
- pathfinding;
- line of sight;
- fog of war;
- бойова система;
- економіка;
- ШІ;
- юніти та групи;
- ППО/радари;
- логістика;
- об'єкти;
- збереження;
- дані балансу.

Окремо адаптуються:

- сенсорний ввід / миша + клавіатура;
- UI;
- графічні налаштування;
- файлові шляхи та системні інтеграції.

## 3.3. Продуктивність

Гра покрокова, тому більшість систем мають бути **event-driven**, а не перераховуватися щокадру.

| Система | Коли перераховується |
|---|---|
| Line of sight | після руху / зміни видимості |
| Fog of war | після зміни видимості |
| Радар | при русі повітряної цілі / зміні сектора |
| ППО | при вході повітряної цілі в зону ураження |
| Pathfinding | коли потрібен новий маршрут |
| Дохід | за правилами ходу/раунду |
| Автовідновлення | за правилами ходу/раунду |
| ШІ | лише під час ходу ШІ |

Для майбутньої великої карти одразу передбачити:

- чанки/сектори;
- кешування;
- LOD;
- sleeping далеких регіонів;
- активні складні розрахунки переважно біля фронту.

# 4. Черговість ходів і бойові дії

## 4.1. Черговість

Використовується **повний хід сторони**:

1. На початку нового раунду всім відповідним юнітам відновлюються очки пострілу.
2. Повний хід виконує Сторона A.
3. Повний хід виконує Сторона B.
4. Починається новий раунд.

Це правило важливе: очко пострілу **не відновлюється на початку власного ходу сторони**, а тільки одночасно на початку нового раунду.

## 4.2. Рух і атака

Для більшості наземних бойових юнітів:

- можна використати **всю доступну дальність руху**;
- після цього атакувати, якщо очко пострілу не витрачене;
- **після атаки подальший рух у цьому ході заборонено**.

Виняток: ударний вертоліт може `рух → атака → залишок руху`.

## 4.3. Вогонь у відповідь

Можуть вести вогонь у відповідь:

- піхота;
- танк;
- БМП;
- БТР;
- бронемашина.

Умова: очко пострілу в поточному раунді ще не використане. Контратака витрачає це саме очко.

Не ведуть вогонь у відповідь:

- ствольна артилерія;
- РСЗВ;
- ударний вертоліт;
- логістика.

ППО працює за окремою автоматичною логікою.

---

# 5. Базова бойова модель

- У кожного юніта є HP.
- Зброя має різну ефективність проти різних типів цілей.
- Базові класи цілей: піхота, легка техніка, важка бронетехніка, вертольоти, літаки.
- Повноцінну систему бронепробиття поки не вводимо.
- Точність, шанс промаху, модифікатори дальності та частина формул шкоди — відкладені на балансування.
- Базові стрільці можуть атакувати бронетехніку, але завдають їй дуже мало шкоди.
- Базові стрільці не атакують вертольоти.
- Танк не атакує вертольоти.
- БТР/БМП/бронемашина можуть атакувати вертоліт **лише якщо конкретне озброєння моделі це дозволяє**.
- Артилерія та РСЗВ не атакують вертольоти.
- ППО не атакує наземні цілі.

# 6. Класи та ролі юнітів

Клас відповідає на питання **«що це за юніт?»**. Роль відповідає **«для чого його найкраще використовувати?»**.

Роль сама по собі **не дає бонусів**. Вона є тегом для ШІ, UI, сортування, фільтрів і підказок.

| Клас | Базова роль |
|---|---|
| Піхота | захоплення / протипіхотна |
| Танк | штурм / протиброньова |
| БМП | вогнева підтримка / транспорт |
| БТР | транспорт / легка підтримка |
| Бронемашина | розвідка |
| Ствольна артилерія / САУ | далека точкова підтримка |
| РСЗВ | площинне ураження |
| ППО | протиповітряна оборона |
| Радар | виявлення |
| Логістика | постачання / ремонт |
| Вантажівка | транспорт / підтримка |
| Ударний вертоліт | мобільний протиброньовий удар |
| Літак | авіаційна підтримка / патрулювання |

Стартовий наземний набір класів:

- піхота;
- танк;
- артилерія;
- РСЗВ;
- ППО;
- радар;
- логістика;
- БТР;
- БМП;
- бронемашина;
- вантажівка.

# 7. Класи озброєння і бонус групи

Озброєння абстрактно ділиться на три класи:

| Клас озброєння | Типовий приклад | Бонус бойової групи |
|---|---|---:|
| Легке | кулемети та подібне | +10% шкоди |
| Середнє | автоматичні гармати | +15% шкоди |
| Важке | великокаліберні гармати / потужні ракети | +20% шкоди |

## 7.1. Дві бойові машини

Бонус визначається за **найслабшим класом озброєння** в парі.

Приклад: танк із важким озброєнням + БМП із середнім = **+15%** до шкоди групи.

## 7.2. Піхота + транспорт

Для піхоти клас її стрілецької зброї **не обмежує** бонус транспорту.

- Для `піхота + БТР/БМП` бонус шкоди визначається класом озброєння транспортної машини.
- `піхота + бронемашина` має спеціалізацію на рух/огляд, а не на підсилення шкоди.
- `піхота + вантажівка` дає мобільність, а не бонус до шкоди.

# 8. Система групування

## 8.1. Загальні правила

- Максимум **2 юніти в одному гексі як група**.
- Використовується **білий список дозволених комбінацій**. Якщо пари немає в дозволених — групування заборонене.
- Групу можна розділити назад.
- Пошкоджені юніти можна об'єднувати.
- Кожен компонент групи зберігає власний HP.
- При отриманні шкоди вона розподіляється між двома компонентами; точна формула ще не визначена.
- Якщо один компонент знищено, другий автоматично залишається окремим юнітом у тому самому гексі.
- Ремонтний ресурс логістики при ремонті групи автоматично розподіляється між компонентами; точна формула ще не визначена.

## 8.2. Боєкомплект групи

- Група має **спільний абстрактний показник БК**.
- Це не буквально однакові фізичні снаряди; це агрегований показник бойового запасу.
- При розділенні залишок БК ділиться порівну між двома компонентами.
- Правило округлення непарного залишку ще не визначене.

## 8.3. Рух групи

- Два однакові юніти: базова дальність руху типу **−1 гекс**.
- Два різні бойові юніти: дальність руху дорівнює швидкості **повільнішого** компонента.
- Піхота + транспорт: спеціальні бонуси нижче.

## 8.4. Дозволені комбінації

| Комбінація | Статус | Ефект |
|---|:---:|---|
| Піхота + піхота | Ні | не дозволено |
| Піхота + БМП | Так | рух +1; бонус шкоди за озброєнням БМП |
| Піхота + БТР | Так | рух +2; бонус шкоди за озброєнням БТР |
| Піхота + бронемашина | Так | рух +2; бонус до огляду |
| Піхота + вантажівка | Так | рух +2; вантажівка втрачає логістичні функції в цій групі |
| Танк + танк | Так | бонус за найслабшим класом озброєння; рух −1 |
| Танк + БМП | Так | бонус за найслабшим класом озброєння; рух по повільнішому |
| Танк + БТР | Ні | — |
| Танк + бронемашина | Ні | — |
| БМП + БМП | Так | бонус за найслабшим класом озброєння; рух −1 |
| БТР + БТР | Так | бонус за найслабшим класом озброєння; рух −1 |
| Бронемашина + бронемашина | Так | бонус за найслабшим класом озброєння; рух −1 |
| БТР + БМП | Ні | — |
| БТР + бронемашина | Ні | — |
| БМП + бронемашина | Ні | — |
| Ствольна артилерія + ствольна артилерія | Так | бонус за класом озброєння; рух −1 |
| Ствольна артилерія + вантажівка | Так | вантажівка збільшує БК; величина залежить від моделі; також підтримує мобільність |
| РСЗВ + РСЗВ | Так | бонус за класом озброєння; рух −1 |
| РСЗВ + вантажівка | Так | вантажівка збільшує БК; величина залежить від моделі; також підтримує мобільність |
| ППО + ППО | Ні | кожна система окрема |
| ППО + радар | Ні | взаємодіють через мережу, не групуються |
| Радар + будь-який юніт | Ні | радар завжди окремий |
| Логістика + логістика | Так | запас ресурсу «припаси» складається; рух −1 |
| Вертоліт + та сама модель вертольота | Так | бонус за класом озброєння; рух −1 |
| Два різні вертольоти | Ні | — |

# 9. Піхота і транспорт

## 9.1. Піхота

- Базова піхота слабка.
- На старті є один тип: **стрільці**.
- Під час купівлі в майбутньому можна буде обирати **тип піхоти**; інші типи відкладені.
- Під час купівлі можна також обрати транспорт.
- Піхота — **єдиний клас, який захоплює ключові точки**.
- Без транспорту рухається повільніше.

## 9.2. БТР

- Дешевший за БМП.
- Менше HP.
- Слабше озброєння.
- Вища мобільність.
- У групі з піхотою: +2 до руху піхоти + бонус шкоди відповідно до озброєння БТР.

## 9.3. БМП

- Дорожча.
- Більше HP.
- Сильніше озброєння.
- Менша мобільність за БТР.
- У групі з піхотою: +1 до руху піхоти + бонус шкоди відповідно до озброєння БМП.

## 9.4. Бронемашина

Жорстко закріплена роль **розвідки**.

Переваги:

- найнижча/низька ціна;
- висока мобільність;
- **найкращий огляд серед наземної бронетехніки**;
- підвищене маскування в лісі та забудові.

Недоліки:

- низький HP;
- слабке озброєння;
- у прямому бою повинна поступатися БТР і БМП.

У групі з піхотою: +2 руху + бонус до огляду.

## 9.5. Вантажівка з піхотою

- +2 до руху піхоти.
- Не дає бонусу до шкоди.
- Поки вантажівка в групі з піхотою, вона **не використовує логістичні функції**.

# 10. Танк

- Основний важкий юніт прямого бою.
- Високий HP.
- Висока ціна.
- Сильний проти бронетехніки.
- Слабший проти піхоти, ніж спеціалізовані протипіхотні засоби.
- Середня мобільність.
- Може атакувати після повного використання руху.
- Після атаки рух завершується.
- Може вести вогонь у відповідь, якщо очко пострілу не витрачене.
- Не атакує вертольоти.
- Групується тільки з іншим танком або з БМП.

# 11. Артилерія і РСЗВ

Артилерія — загальний клас, у якому ствольна артилерія/САУ та РСЗВ є різними підтипами.

## 11.1. Ствольна артилерія / САУ

- Б'є по **одному гексу**.
- Може вести вогонь по цілі, яку бачить будь-який союзний юніт у спільній розвідувальній мережі.
- Власна пряма видимість не обов'язкова.
- Не веде вогонь у відповідь.
- Не атакує вертольоти.
- Різні моделі можуть мати різні дальність, шкоду, БК, потребу в розгортанні та мобільність.
- Деякі системи можуть стріляти майже одразу, інші потребують розгортання.

## 11.2. РСЗВ

- Уражає **кілька гексів**.
- Центральна/основна зона отримує найбільшу шкоду, далі шкода зменшується.
- Кожна модель має власний шаблон площі ураження.
- Відрізняються дальністю, площею, шкодою, БК, потребою в розгортанні, ціною та мобільністю.
- Не ведуть вогонь у відповідь.
- Не атакують вертольоти.

## 11.3. Групи артилерії

- `артилерія + артилерія` та `РСЗВ + РСЗВ`: бонус шкоди за загальним правилом класу озброєння, рух −1.
- `артилерія + вантажівка` та `РСЗВ + вантажівка`: вантажівка є винятком і збільшує БК артсистеми; точний бонус залежить від конкретної моделі вантажівки.

---

# 12. ППО і радари

## 12.1. Загальна логіка ППО

Кожна модель ППО унікальна. Варіанти:

- кругова зона ураження;
- секторна зона з більшою дальністю;
- система без розгортання, але з меншою дальністю та/або БК;
- інші комбінації характеристик.

Для секторної ППО:

- напрямок сектора обирає гравець під час розгортання;
- сектор можна змінити окремою дією без повного згортання.

ППО:

- атакує тільки повітряні цілі;
- не атакує наземні цілі;
- максимум **1 постріл за хід/раундовий цикл пострілу**;
- має власний запас пострілів, який залежить від моделі;
- стріляє автоматично по найближчій доступній виявленій цілі;
- для пострілу потрібні виявлення, зона ураження, БК та доступне очко пострілу.

## 12.2. Радари

- Окремі юніти, не групуються ні з ким.
- Виявляють тільки повітряні цілі: літаки та вертольоти; майбутні БПЛА можуть бути додані пізніше.
- Наземні цілі радаром не виявляються.
- Можуть мати кругову або секторну зону.
- Для секторного радара напрямок задається при розгортанні.
- Напрямок сектора можна змінювати окремою дією.
- Дальність залежить від моделі.
- Рельєф, ліс та забудова поки не блокують радарне виявлення.
- Радар можна фізично знищити.
- РЕБ та радіоелектронне подавлення поки відсутні.

## 12.3. Спільна розвідувальна мережа

- Якщо один союзний юніт/сенсор виявив ціль, інформація доступна іншим дружнім юнітам.
- ППО може стріляти по цілі, яку саме не бачить, якщо її бачить радар/мережа та ціль у зоні ураження.
- Та сама логіка застосовується до артилерії й ударних вертольотів для наземних цілей.

---

# 13. Ударні вертольоти

На старті є тільки **ударні вертольоти**. Транспортні та розвідувальні вертольоти відкладені.

## 13.1. Бойова роль

- Основна спеціалізація: танки та інша бронетехніка.
- По піхоті менш ефективні.
- Атакують тільки наземні цілі.
- Не атакують літаки або інші вертольоти.

## 13.2. Рух і атака

- Повноцінний юніт на карті.
- Не прив'язаний до конкретного аеродрому.
- Може рухатися й атакувати в одному ході.
- Може `рух → атака → залишок руху`.
- Максимум **1 атака за хід**.
- Не веде вогонь у відповідь.
- Базова дальність атаки: **3 гекси**.
- Дальність руху залежить від конкретної моделі.
- БК залежить від конкретної моделі.
- Розгортання перед атакою не потрібне.

## 13.3. Простір і ППО

- Вертоліт може пролітати над зайнятими дружніми та ворожими гексами.
- Завершити хід може тільки на **вільному гексі**.
- Наземний юніт/група і вертоліт/група вертольотів не можуть одночасно завершувати хід в одному гексі.
- Може входити в зону ППО.
- Якщо ППО атакувало вертоліт під час руху і він вижив, вертоліт **втрачає весь залишок руху**, але може атакувати, якщо ще має доступну атаку.

## 13.4. Виявлення

- Власна дальність огляду залежить від моделі.
- Ліс і забудова ускладнюють самостійне виявлення наземних цілей.
- Якщо наземну ціль бачить будь-який союзний юніт, вертоліт може отримати цілевказання через спільну мережу й атакувати її в межах дальності.

## 13.5. Групування

- Можна об'єднати тільки **два однакові вертольоти однієї моделі**.
- Бонус шкоди — за класом озброєння.
- Рух групи −1 гекс.

## 13.6. Аеродром

Аеродром для вертольота — лише сервісна точка, а не домашня база.

- Ремонт тільки на функціональному аеродромі.
- Поповнення БК тільки на функціональному аеродромі.
- Логістика в полі вертоліт не ремонтує.
- Вертоліт не займає слоти місткості аеродрому.
- Може залишатися на аеродромі необмежено довго без штрафу.
- На аеродромі може бути атакований як звичайний юніт.
- Не отримує додаткового захисту від аеродрому.
- Якщо аеродром знищено, вертоліт **не знищується автоматично**.
- Після прибуття на аеродром обслуговування починається з наступного ходу.
- На функціональному аеродромі: +15% max HP за хід; БК повністю відновлюється за 1 хід.
- Обслуговування безкоштовне.
- Після отримання обслуговування вертоліт може того ж ходу покинути аеродром.

---

# 14. Літаки

Літаки працюють інакше за вертольоти.

## 14.1. Базування

- Літаки базуються на аеродромах.
- У майбутньому можливі авіаносці, але морська система відкладена.
- Аеродром має обмежену місткість літаків.
- Усі аеродроми поки одного базового типу.
- Точна місткість ще не визначена.

## 14.2. Бойовий виліт

- Літак не стоїть постійно на полі бою як гексовий юніт.
- Гравець обирає літак і режим.
- Для атаки: аеродром → ціль → аеродром.
- Якщо маршрут проходить через ППО, ППО може атакувати літак.
- Якщо літак не знищений, він продовжує місію навіть після отримання шкоди.
- Після удару повертається на базу.

## 14.3. Озброєння та економіка

- У літака немає окремого звичайного запасу БК як у наземних юнітів.
- Перед кожним бойовим вильотом обирається доступний тип озброєння.
- Вартість бойового застосування залежить від обраного озброєння.
- Наприклад, бомбовий удар та крилата ракета мають різну вартість.
- Конкретні ціни не визначені.

## 14.4. Патрулювання

- Режими: **атака** або **патрулювання**.
- Для патрулювання гравець обирає конкретний гекс/точку.
- Літак патрулює зону навколо цієї точки в межах своєї дальності.
- Патрулювання триває, доки гравець не скасує його.
- Якщо патрульний літак був атакований, він припиняє патрулювання і повертається на базу.
- Патрульний літак може перехоплювати будь-які підтримувані грою повітряні цілі; зараз літаки та вертольоти, у майбутньому БПЛА.
- Перехоплення — **один автоматичний постріл**, без окремого повітряного бою.
- Максимум одне перехоплення за хід.
- Якщо відбулося перехоплення, списуються кошти.
- Вартість застосування залежить від типу/можливостей літака; точна формула не визначена.

## 14.5. Стан літака

- Літак має HP.
- Може виконувати новий виліт із неповним HP, якщо HP > 0.
- На аеродромі автоматично відновлює певну кількість HP щохід; **точний відсоток для літака ще не зафіксований**.
- Окремої затримки на техобслуговування немає.

## 14.6. Перебазування

- Літак можна перебазовувати між дружніми аеродромами.
- Перебазування платне.
- Чим більша відстань, тим вища вартість.
- Точна формула не визначена.

## 14.7. Втрата аеродрому

- Якщо ворожа піхота захоплює аеродром, усі ворожі літаки, що лишилися на ньому, знищуються.
- Якщо аеродром повністю знищено, усі літаки, що знаходилися на ньому, знищуються.
- Вертольоти під це правило не підпадають.

---

# 15. Логістика

## 15.1. Логістичні машини

- Неозброєні.
- Не атакують і не контратакують.
- Мають власний ресурс **«припаси»**.
- За одну дію обирають одне:
  - поповнити БК;
  - відремонтувати/відновити HP техніки або піхоти;
  - ремонтувати відповідні об'єкти/мости за правилами.
- Запас «припасів» відновлюється тільки на базі або в місті.
- У полі сам не регенерує.

## 15.2. Бази та міста

- Ремонт і поповнення БК відбуваються **одночасно**.
- За ефективністю базове поповнення/ремонт задумане рівноцінним логістичній машині; точні числові значення ще не зафіксовані.
- Логістична машина відрізняється обмеженим власним запасом і необхідністю вибирати одну дію.

## 15.3. Різні моделі логістики

Можуть відрізнятися:

- місткістю «припасів»;
- дальністю руху;
- HP;
- ціною.

Наприклад: велика повільна, швидка мала, захищена дорога.

## 15.4. Група логістики

- `логістика + логістика`: запаси «припасів» просто складаються.
- Рух −1 гекс.

---

# 16. Економіка і ліміт армії

## 16.1. Дохід

- Стартовий бюджет.
- Мінімальний гарантований базовий дохід щохід/за економічний цикл.
- Додатковий дохід від контрольованих ключових об'єктів.
- Навіть при втраті всіх економічних точок дохід не падає до нуля.
- Різні типи об'єктів можуть давати різний дохід.

## 16.2. Купівля

- Уся техніка сторони доступна одразу; дерева технологій немає.
- Нові юніти купуються під час кампанії.
- Після купівлі з'являються миттєво у відповідній контрольованій точці.
- Наземні юніти — військові бази.
- Піхота — також міста.
- Літаки — аеродроми.
- Порти/кораблі — майбутня морська система.
- Точка появи ударних вертольотів як куплених юнітів **ще не зафіксована окремо**.

## 16.3. Армійський ліміт

- Є загальний ліміт армії в очках.
- Різні класи займають різну кількість очок ліміту.
- Ліміт можна перевищувати.
- Перевищення зменшує дохід за хід.
- Чим більше перевищення, тим більший штраф.
- Деякі ключові об'єкти можуть збільшувати ліміт.
- Точні формули/значення не визначені.

---

# 17. Досвід і стан юнітів

- Кожен конкретний юніт отримує досвід.
- Досвід дає невеликі бонуси.
- Конкретна система рівнів/бонусів відкладена.
- Мораль та пригнічення поки відсутні.
- Класичної моралі немає; замість неї прийнято **боєздатність від постачання** (див. §38, реалізацію відкладено).
- Ворожу техніку не можна захоплювати.
- Після знищення юніта його знищена модель/спрайт лишається на карті ще **1 хід**, потім зникає.

---

# 18. Ключові об'єкти

## 18.1. Типи

Можливі:

- міста;
- військові бази;
- аеродроми;
- у майбутньому порти та інші стратегічні об'єкти.

Об'єкти можуть займати кілька гексів.

## 18.2. Захоплення

- Захоплює тільки піхота.
- Кожен великий об'єкт має **один спеціальний гекс контролю**.
- Гекс контролю може розташовуватися в різних місцях, не обов'язково в центрі.
- Коли піхота захоплює цей гекс, **весь об'єкт миттєво переходить під контроль** сторони.
- Ворожі юніти можуть залишатися на інших клітинках об'єкта.
- Після зміни контролю ворожі юніти зберігають тільки захисний бонус місцевості/забудови; ремонт, поповнення, дохід та інші функції об'єкта їм недоступні.
- Усі гекси всередині одного об'єкта функціонально однакові; спеціалізованих внутрішніх зон поки немає. Виняток — гекс контролю.

## 18.3. Захист і супутня шкода

- Об'єкт сам не стріляє.
- Юніт на клітинці об'єкта може отримувати захисний бонус залежно від типу об'єкта.
- Приклад: місто — сильний; база — помірний; аеродром — мінімальний.
- Захисний бонус **не залежить від HP об'єкта** і зберігається навіть у зруйнованому стані як укриття/руїни.
- Якщо атакують юніт/групу, що стоїть на клітинці об'єкта, об'єкт отримує **10% від сумарної шкоди** як collateral damage.

## 18.4. Пряма атака по об'єкту — канонічне уточнення

Звичайні танки/БМП тощо не повинні просто стріляти по порожньому місту.

Але спеціально призначене важке озброєння може напряму атакувати стратегічні об'єкти:

- артилерія;
- РСЗВ;
- авіаудари;
- інші спеціальні системи, якщо будуть додані.

Таким чином існують два канали шкоди:

1. атака по юніту на об'єкті → 10% collateral;
2. спеціальна пряма атака по самому об'єкту → окрема нормальна шкода.

## 18.5. HP і відновлення

- Об'єкт має HP.
- Може мати UI-стани: нормальний / пошкоджений / критичний / знищений.
- Якщо HP > 0, об'єкт автоматично відновлює **5% максимального HP за хід**.
- Отримання нової шкоди не ставить це автовідновлення на паузу.
- Якщо HP = 0, об'єкт знищений і автоматичне відновлення не працює.
- Логістична/ремонтна машина повинна відновити його мінімум до **25% HP**.
- Після досягнення 25% об'єкт **одразу повертає повну функціональність** і далі автоматично відновлює 5% за хід.
- Поточний канон щодо функціональності: ключова межа — знищений/відновлений; проміжні HP-стани насамперед потрібні для UI/візуалу, якщо окремо не буде погоджено інше.
- Піхота може захопити об'єкт у будь-якому стані; поточний HP зберігається після захоплення.

# 19. Terrain, line of sight і fog of war

## 19.1. Базові типи місцевості

У першій версії:

- поле / рівнина;
- ліс;
- забудова / місто;
- болото / складний ґрунт;
- вода.

Пізніше можна додати пустелю, сніг, гори та інші біоми.

## 19.2. Один основний тип на гекс

- Візуально гекс може містити змішані елементи.
- Для геймплею він має один **основний тип** місцевості.
- Не рахуємо відсотки лісу/поля всередині гекса.
- Дороги, річки та об'єкти — окремі шари.

## 19.3. Line of sight

- Повноцінний LOS.
- Ліс, забудова та інші відповідні перешкоди можуть блокувати/обмежувати звичайний огляд.
- Реальна висота рельєфу поки не бере участі в розрахунку LOS.

## 19.4. Fog of war

- Динамічний.
- Якщо територію більше ніхто не бачить, вона знову приховується.
- Зберігається останній відомий стан місцевості.
- Ворожий юніт після втрати контакту **повністю зникає**; маркер останньої позиції не лишається.

## 19.5. Маскування

- Базово залежить переважно від місцевості.
- Піхота та відповідні юніти в лісі/забудові можуть бути менш помітними.
- Бронемашина має окремо зафіксований бонус маскування в лісі/забудові.

---

# 20. Дороги

Є три класи:

1. магістраль / шосе;
2. звичайна асфальтована дорога;
3. ґрунтова дорога.

Точні бонуси руху поки не визначені.

Канонічні правила:

- якщо юніт рухається дорогою, **дорога повністю замінює штраф місцевості до руху**;
- шосе через ліс для руху працює так само, як шосе через поле;
- це не скасовує вплив лісу/забудови на огляд, маскування та захист;
- дороги всередині міст/сіл залишаються повноцінним дорожнім шаром і дають ті ж бонуси руху;
- дорога всередині гекса завжди проходить через **центр гекса**;
- прості перехрестя можуть бути будь-де;
- складні дорожні вузли тяжіють до міст, сіл, ключових об'єктів і стратегічних напрямків;
- ґрунтові дороги можуть самостійно з'єднувати села, поля, ліси та другорядні об'єкти;
- через великі болота дороги проходять рідко, переважно одним вузьким маршрутом/насипом.

---

# 21. Річки, вода, мости, амфібійність

## 21.1. Річки

Комбінована система:

- вузькі річки проходять **по межах між наземними гексами**;
- широкі річки, озера, водосховища та інші великі водойми займають **водні гекси**;
- віднесення до вузьких/широких залежить від масштабу конкретної карти, без жорсткого порога в метрах.

## 21.2. Мости

- Генеруються тільки там, де **дорога перетинає річку**.
- На великих річках може бути кілька мостів, але вони відносно рідкісні й стратегічно важливі.
- Реальні мости з геоданих — основа, але генератор може прибирати другорядні або додавати нові заради балансу.
- Мости можуть бути пошкоджені або знищені.
- Знищений міст блокує звичайний перехід до ремонту.
- Окремих інженерних юнітів поки немає; ремонтують логістичні/ремонтні машини.

## 21.3. Амфібійні юніти

- Звичайні наземні юніти не можуть рухатися по великих водних гексах.
- Амфібійна техніка може.
- У воді амфібійна техніка рухається **повільніше, ніж по суші**.
- У водному гексі вона **не може атакувати**, тільки рухатися.
- Вихід із води можливий лише через придатні берегові гекси.
- Базове правило придатності задає тип берега: пологий/пляжний — доступний; крутий/скелястий — недоступний.
- Редактор карти може вручну перевизначити доступність конкретної берегової ділянки.

---

# 22. Дружній вогонь

- Звичайні точкові атаки своїх юнітів не пошкоджують.
- Дружній вогонь існує для **атак по площі**.
- Артилерійські/авіаційні/інші AoE-атаки можуть пошкодити союзні юніти, якщо ті потрапили в зону ураження.

---

# 23. Кампанія, ШІ та збереження

## 23.1. Кампанія

- Одна довга кампанія на одній безперервній карті.
- Усі позиції, пошкодження, досвід, контроль об'єктів, економіка та склад армії зберігаються в межах кампанії.
- Перемога: захоплення всіх ключових точок противника.

## 23.2. ШІ першої версії

Простий тактичний:

- рух до ключових точок;
- атака доступних цілей;
- пріоритет найближчих/уразливих цілей;
- використання піхоти для захоплення.

Складні резерви, оперативне планування, глибока логістика ШІ — пізніше.

## 23.3. Збереження — чинне рішення

- **Автозбереження наприкінці кожного ходу.**
- Ручні збереження в поточному каноні окремо не зафіксовані.

---

# 24. Загальна система формування карт

## 24.1. Основний принцип

Карти базуються на **реальних частинах держав**.

Вибраний підхід: **впізнавана реальна географія з ігровою адаптацією**.

Зберігаємо:

- основні міста;
- великі річки;
- ключові дорожні напрямки;
- великі лісові масиви;
- водойми;
- характерну берегову лінію;
- великі цивільні аеропорти/порти за потреби.

Спрощуємо:

- дрібні дороги;
- дрібні вигини берегів;
- другорядні поселення;
- дрібні лісосмуги, якщо масштаб не дозволяє;
- точну метричну відповідність.

Суто військові об'єкти (бази тощо) переважно розміщуються процедурно для балансу та геймплею.

## 24.2. Гібридна генерація

- Процедурний генератор створює основу.
- Після генерації карту можна вручну редагувати.
- Використовується seed: однаковий seed → однакова процедурна основа.
- Ручні зміни зберігаються поверх неї.

## 24.3. Геодані

Комбінований імпорт:

- основні дороги, річки, водойми, ліси, населені пункти, великі цивільні аеропорти/порти імпортуються з реальних геоданих;
- генератор адаптує їх до гексів;
- дрібні деталі спрощуються;
- дизайнер може вручну виправляти результат.

## 24.4. Тестова карта

Перший прототип: **40×20 гексів (40 завширшки × 20 заввишки) = 800 клітинок**.

> Узгоджено 27.09.2026: замість початкових 20×20 лишаємо вже вбудовану карту 40×20 (горизонтальна орієнтація телефона).

Це тестове середовище, а не фінальний масштаб кампанії.

---

# 25. Pipeline генерації карти

Рекомендований канонічний pipeline:

1. Вибір реального регіону та масштабу.
2. Імпорт/спрощення базових геоданих.
3. Побудова гексової маски та меж карти.
4. Визначення великих областей місцевості.
5. Вода, річки, берегова лінія.
6. Реальні міста/села та цивільні об'єкти.
7. Стратегічні генераторні зони: стартові, центральна зона конфлікту, тилові.
8. Процедурне розміщення військових об'єктів.
9. Головні магістралі.
10. Локальні дороги між об'єктами.
11. Мости там, де дороги перетинають річки.
12. Деталізація лісів, полів, боліт, передмість.
13. Підбір шаблонів і візуальних варіацій гексів.
14. Перевірка прохідності, ізольованих зон, chokepoints і стартового балансу.
15. Ручне редагування дизайнером.

---

# 26. Ідеї Dorfromantik, прийняті для генератора

Не копіювати гру буквально; використати принципи.

## 26.1. Краї гекса

Для генератора/графіки гекс може мати характеристики шести країв. Наприклад центр — поле, а краї містять ліс/дорогу/поле. Це допомагає:

- стикувати ліси;
- робити природні межі;
- правильно продовжувати дороги;
- уникати розривів річок;
- підбирати спрайт/шаблон.

Для геймплею це все одно один гекс з одним основним типом.

## 26.2. Бібліотека архетипів

Мати шаблони:

- суцільний ліс;
- край лісу;
- лісосмуга;
- дорога через ліс;
- поле біля лісу;
- берег;
- передмістя;
- квартал;
- промзона;
- інші.

## 26.3. Мережі спочатку

Річки та дороги не розкидати випадково по гексах. Спочатку будується зв'язна мережа/маршрут, потім підбираються візуальні варіанти клітинок.

## 26.4. Seed і параметри щільності

Майбутні параметри генератора можуть включати:

- лісистість;
- частку забудови;
- воду;
- болота;
- щільність доріг;
- кількість ключових об'єктів;
- інші параметри.

## 26.5. Автоматична оцінка якості

Генератор може штрафувати:

- дорогу, що безглуздо обривається;
- річку без логічного продовження;
- недоступну ключову точку;
- ізольований регіон;
- некоректну переправу;
- надмірно сильну стартову позицію.

І заохочувати:

- зв'язні дороги;
- природні лісові межі;
- логічні мости;
- альтернативні маршрути;
- впізнавану географію.

---

# 27. Формування типів місцевості

## 27.1. Ліси

- Переважно великі зв'язні масиви.
- Також невеликі лісосмуги та компактні групи.
- Не випадковий шум по окремих гексах.
- Межа може візуально заходити на сусідній гекс, не змінюючи його ігровий тип.

## 27.2. Болота / складний ґрунт

- Великі зв'язні зони, переважно біля води та низин.
- Також локальні невеликі ділянки.
- Через великі болота дороги проходять рідко.

## 27.3. Поля / відкриті території

Форма залежить від реального регіону:

- десь великі суцільні поля;
- десь розбиті лісосмугами, селами, дорогами й невеликими лісами.

## 27.4. Забудова

- Великі міста — ключові об'єкти.
- Окрім них можуть бути села, передмістя, окремі квартали, промислові й невеликі забудовані зони.
- Неключова забудова не має гекса контролю, але впливає на рух/огляд/маскування/захист за правилами місцевості.
- Форма великого міста залежить від реального міста: компактна, витягнута вздовж дороги/річки, ядро + передмістя тощо.
- Будівлі/паркани/двори можуть візуально заходити на сусідній гекс без зміни його правил.

---

# 28. Дорожня генерація

Використовується комбінована схема:

- кілька головних магістралей;
- локальні дороги, що з'єднують міста, села, бази, аеродроми та інші важливі точки;
- ґрунтові дороги можуть утворювати власну другорядну мережу між селами/полями/лісами.

Мости створюються лише при перетині дороги з річкою.

---

# 29. Річкова та берегова генерація

- Кількість і структура річок залежать від реального регіону, seed і параметрів адаптації.
- На малих картах генератор повинен уникати надмірної кількості водних бар'єрів.
- Великі затоки, півострови, острови, водосховища та інші впізнавані форми зберігаються.
- Дрібні вигини берегової лінії спрощуються відповідно до масштабу.
- Придатність берега для амфібій має базове правило за типом берега + ручний override в редакторі.

---

# 30. Стратегічні генераторні зони

Використовуються всі три:

- стартові зони сторін;
- центральна зона конфлікту;
- тилові зони.

Це **службова інформація генератора**, а не окрема система контролю території.

Призначення:

- логічне розміщення стартових сил;
- розподіл військових об'єктів;
- формування транспортних напрямків;
- баланс відстаней до ключових точок;
- уникнення випадкової сильної переваги однієї сторони.

Стартові позиції повинні визначатися логікою реального регіону та сценарію, але проходити автоматичну перевірку балансу.

---

# 31. Межі карти

- Основою є реальний регіон.
- Межі можна коригувати під зручну гексову форму.
- Не можна випадково обрізати критичне місто, дорогу, річку чи ключовий об'єкт.
- За межами ігрової карти **нічого не відображається**; декоративного продовження немає.
- Залізниці в першій версії взагалі не додаються.

---

# 32. Візуальні шаблони карти

Вибрано **шаблони з варіаціями**.

- Є підготовлені одно- та багатогексові шаблони лісів, забудови, баз, аеродромів тощо.
- Усередині шаблону можна варіювати моделі, кількість і розташування декоративних деталей.
- Це знижує повторюваність і водночас дозволяє оптимізувати рендер.
- Бажано батчити/об'єднувати декоративні елементи, щоб десятки дерев не ставали десятками важких ігрових об'єктів.

---

# 33. Відкладено / не визначено

Не приймати рішення самостійно без обговорення:

- точні HP усіх моделей;
- точні значення шкоди;
- формула точності/промахів;
- бронепробиття;
- точні дальності більшості наземних юнітів;
- конкретний список моделей Сторони A/B;
- точні ціни юнітів;
- точні очки ліміту;
- формула штрафу за перевищення ліміту;
- точні доходи об'єктів;
- точні бонуси трьох типів доріг;
- точна формула розподілу шкоди між компонентами групи;
- округлення БК при розділенні;
- відсоток авторемонту літаків;
- точна місткість аеродрому;
- точна економіка бойових вильотів/перехоплень/перебазування;
- точка появи куплених ударних вертольотів;
- інші типи піхоти;
- БПЛА;
- РЕБ;
- погода;
- день/ніч;
- флот;
- інженерні юніти;
- залізниця;
- геймплейна система висот;
- складний стратегічний ШІ;
- ручні збереження;
- майбутні ролі/класи, яких ще немає.

# 34. Скасовані або замінені рішення — НЕ ВИКОРИСТОВУВАТИ

Цей розділ критично важливий для handoff.

| Старе рішення | Чинне рішення |
|---|---|
| `Танк + танк` завжди +20% | Загальне правило бонусу за найслабшим класом озброєння |
| `БМП + БМП` фіксовано +20% | Загальне правило класу озброєння |
| `БТР + БТР` +15% і +1 рух | Загальне правило класу озброєння; як однакова група рух −1 |
| `Бронемашина + бронемашина` фіксовано +10% | Загальне правило класу озброєння |
| `Артилерія + артилерія` / `РСЗВ + РСЗВ` +25% | Загальне правило класу озброєння; рух −1 |
| Усі групи мають −1 рух | Тільки однакові юніти мають −1; змішані рухаються по повільнішому; транспорт піхоти має свої бонуси |
| `Піхота + вантажівка` +25% БК | Скасовано: звичайно вантажівка дає піхоті лише +2 руху; артилерія/РСЗВ — виняток із додатковим БК |
| Вертоліт веде вогонь у відповідь | Скасовано: вертоліт не контратакує |
| Об'єкт можна пошкодити тільки collateral damage | Скасовано: артилерія, РСЗВ, авіаудари та інші спеціальні важкі системи можуть атакувати об'єкт напряму |
| Поступове падіння функціональності об'єкта за HP — обов'язкове | Поточний канон: при 0 об'єкт не функціонує; після відновлення логістикою до 25% одразу повертається повна функціональність; стани HP насамперед UI/візуал |
| Амфібійна швидкість залежить від моделі | Змінено: у воді всі амфібійні наземні юніти рухаються повільніше, ніж по суші |
| Тестова карта 30×30 | Змінено на **20×20** |
| Глобальна процедурна географія з нуля | Основа — реальні частини держав, адаптовані в гібридному генераторі |

# 35. Рекомендований наступний порядок роботи

Поточний користувацький пріоритет — **продовжити карту**, а не переходити до конкретних моделей техніки.

Рекомендована послідовність:

1. Завершити правила генерації карти й редактора.
2. Визначити структуру даних гекса та edge-масок.
3. Визначити структуру даних доріг, річок, мостів, об'єктів і шаблонів.
4. Визначити імпорт/спрощення реальних геоданих.
5. Продумати UI редактора карти.
6. Побудувати специфікацію тестової карти 40×20.

## 38.1. Прийнято (реалізувати пізніше)

| Механіка | Суть | Примітка |
